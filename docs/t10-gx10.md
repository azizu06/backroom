## Method and evidence

- [Ugly invoice](../fixtures/t10/ugly-invoice.txt): synthetic fax-like invoice with odd ID punctuation, a void amount, line items/tax, and an embedded instruction injection. No real bank details.
- [Invoice JSON Schema](../fixtures/t10/invoice.schema.json): ten required fields, no extras, USD enum, ISO-like date patterns, nonnegative numeric amounts. The script checks those constraints locally and compares all values against a separate answer key. All successful outputs also matched the answer key exactly.
- [Optimized raw results](../fixtures/t10/results.json) and [initial raw results](../fixtures/t10/results-default-reasoning.json) contain all samples, completion counts, outputs, latency, and validity flags.
- Five sequential nonstreaming `/chat/completions` requests per installed model; temperature 0, JSON-object response mode, max 1024 tokens. No samples or cold/model-load costs excluded. p50 is the middle wall-clock latency of five requests, including network, queueing, prefill, and output generation.
- Effective tokens/s is reported completion tokens divided by full wall-clock seconds; it is **not** decode-only GPU throughput. Completion accounting can include reasoning tokens. Models used different output token counts, so tokens/s alone is not a task-speed comparison.
- Reproduce from repo root: `pnpm --filter @backroom/orchestrator exec tsx src/router/measure-t10.ts`. This overwrites the optimized results file; it does not call cloud services.

## Model choices

| Task | Recommendation | Evidence limit |
| --- | --- | --- |
| Invoice/email extraction | Local `gpt-oss:20b`, low reasoning; Qwen 8B with no reasoning is the backup | 20B was fastest and both passed 5/5 on this invoice |
| Inbox classification, fuzzy reconciliation candidates, post-call summaries | Start with local `gpt-oss:20b`; Qwen is a smaller alternative | Extrapolated from extraction speed, not a task-quality ranking; validate output schema and confidence for each call |
| Call plan, ask-why, ambiguous judgment | Cloud Claude through OpenRouter | Product routing contract; local extraction measurements do not establish judgment quality |
| In-call conversation | Cartesia runtime | Outside this router |

120B is excluded from routine routing: even low reasoning missed the extraction latency bar. If the GX10 becomes unhealthy or rolling completion p50 exceeds 5 s, the router falls back to cloud; three consecutive healthy model-list pings restore it. A cloud-only run must drop the on-site-data claim. See [router API and configuration](../orchestrator/README.md).
